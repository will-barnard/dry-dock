Worker priority & failover

Each worker has a priority integer (lower = more preferred). The dispatcher groups workers in a pool by priority tier and always tries the lowest tier first.

Strict failover rule: if any worker in the preferred tier is capable of the task (right model, enough RAM/VRAM) — even if it's currently busy — the dispatcher waits for it rather than handing the job to a backup. Backup workers (higher priority number) only pick up work when no capable primary is available.

Recommended: set your primary (PC) workers to 1 and your backup (MacBook) workers to 100.

Model fallback chain

  1. Per-task preferred_model if set on the task.
  2. Per-role assignment chosen above (saved to app_settings).
  3. Backend env defaults: DEFAULT_PLANNER_MODEL for the planner role; DEFAULT_CODE_MODEL for every other role.
